# 一个模型配置多个记录类型（ir_recordtype 配置说明）

本文说明如何让一个模型拥有多个记录类型，并配置它的权限、默认值、菜单、列表和表单。以 `pharaccount.account`（药店账户）为例。

## 1. 模型声明（开发者）

模型类上声明类属性：

```python
class PharaccountAccount(models.Model):
    _name = 'pharaccount.account'
    _record_type = True
```

框架（`odoo/orm/models/__init__.py` 的 `MetaModel`）会自动添加字段 `record_type_id`（指向 `ir.record.type`）。升级模块后字段生效。

注意：字段不会自动出现在列表和表单里，需要在视图中手动添加 `<field name="record_type_id"/>`。

## 2. 启用（管理员）

进入 **设置 → 技术 → 数据模型（ir.model）**，打开模型，点击 **Enable Record Types**。

启用时会检查：

- 模型是否声明了 `_record_type`，没有则报错；
- 是否还有非管理员组的**无类型授权**（`ir.access` 中 `record_type_id` 为空、组不是管理员）。有则列出，需要先删除或改为类型授权。

启用后会创建一条管理员无域授权（管理员可见全部记录），并把模型标记为"支持记录类型"。关闭（Disable）时，如果仍有记录引用类型则不允许。

## 3. 创建类型（管理员）

进入 **设置 → 技术 → 记录类型**，新建一条类型：

| 字段 | 说明 |
|---|---|
| 名称 / 编码 | 名称显示给用户，编码在同一模型内唯一 |
| 数据模型 | 选择 `pharaccount.account` |
| 序号 / 启用 | 显示顺序；停用后不能新建或切换到该类型 |
| 父类型 | 同模型的类型，只用于视图扩展链，**不继承权限** |
| 菜单父级（menu_parent_id） | 类型菜单挂在哪个菜单下，空则为顶层菜单 |

类型的页签：

- **权限**：每个组勾选读、写、新建、删除。保存后自动生成一条 `ir.access` 授权行，域为 `record_type_id = 本类型`。没有任何权限的类型对非管理员不可见。
- **默认**：某组默认使用的类型（每组每模型只能有一个）。默认类型必须已经授权给该组。
- **访问行**：自动生成的访问行（只读，供查看）。
- **菜单**：类型生成的动作和菜单（只读）。

## 4. 菜单（自动生成）

创建类型时自动生成：

- 一个**窗口动作**：`domain = [('record_type_id', '=', 类型id)]`，`context = {'default_record_type_id': 类型id}`，视图为列表和表单；
- 一个**菜单**：名称为类型名称，父级为"菜单父级"，可见组为有读权限的组（以及管理员）。

菜单只有在类型启用且有读权限时才可见。例如：

- 药店 → 授权给销售组，菜单可见；
- 连锁总店 → 没有权限，菜单保持停用。

要让类型出现在某个下拉菜单里，设置"菜单父级"为该菜单（例如"主数据管理"）。

## 5. 列表和表单

### 列表
- 类型菜单打开的列表已经按类型过滤（动作的 domain）。
- 列表要显示类型列，需要在模型的列表视图里加 `<field name="record_type_id"/>`（pharaccount 已加）。
- 搜索视图可以加分组过滤：`<filter name="group_record_type" string="记录类型" context="{'group_by': 'record_type_id'}"/>`。

### 表单
- 默认使用模型的表单视图。
- 类型可以有自己的表单视图（扩展视图）：创建一条 `ir.ui.view`，`model` 为模型，`type = form`，`inherit_id` 指向模型的默认表单，并把 `record_type_id` 设为该类型（只写与默认表单的差异，例如隐藏药店专有字段）。
- 类型菜单打开时，动作会使用该类型的表单视图；通过其他入口打开时使用默认表单。
- 注意：目前类型表单界面没有"视图"页签，类型视图需要通过 `ir.ui.view` 设置 `record_type_id`，这是待补充的界面。

## 6. 新建记录时的默认类型

`default_get` 按以下顺序选择：

1. 当前用户所属组在"默认"中的类型（序号小的优先）；
2. 没有默认时，取用户有权新建的第一个类型（按序号）。

从类型菜单新建时，`default_record_type_id` 上下文会直接指定类型。

## 7. 运行时的权限

- 读取：只能看到有读权限的类型的记录；
- 新建、修改类型：需要对该类型有相应权限（写入时检查 `record_type_id` 的变化）；
- 删除：需要类型中该组的删除权限。

无权限时：列表查询返回空结果或访问错误（取决于用户是否有任何匹配的授权行）。

## 8. 完整示例：药店 / 医院 / 医生

1. 开发者：`pharaccount.account` 声明 `_record_type = True`，列表和表单加 `record_type_id`。
2. 管理员：在 `pharaccount.account` 上点击 **Enable Record Types**。
3. 创建三条类型：药店（pharma）、医院（hospital）、医生（doctor），菜单父级都设为"药店（PC）/主数据管理"。
4. 每条类型配置权限：例如医院、医生授权给 `group_user`（读、写、新建），`group_manager` 再加删除。
5. 给 `group_user` 设置默认类型（药店需先授权给该组）。
6. 账户列表中把"示例医院"的类型改为医院。

结果：用户在"主数据管理"下看到医院、医生、药店三个菜单，每个菜单只显示对应类型的账户，并默认新建该类型的记录。

## 9. 已知限制

- 类型表单没有"视图"页签，类型视图需要手动设置 `ir.ui.view.record_type_id`。
- 菜单父级只在创建类型时生成，之后修改需要在菜单上调整或重新保存类型。
- 框架只按动作选择视图，同一条记录从不同菜单打开，布局可能不同。
- 类型的权限是唯一的非管理员授权来源，模型上不能再有无类型的无域授权。
